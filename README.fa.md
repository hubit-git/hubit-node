# hubit-node (فارسی)

[English](README.md) | فارسی

یک نود کوچک VPN برای [هابیت پنل](https://github.com/hubit-git/panel): کاربران SSH (فقط تونل) و OpenVPN روی سرور خودتان. از پنل ادمین
هابیت با یک API از نوع JSON مدیریت می‌شود، یا دستی از خط فرمان. داخل Docker اجرا می‌شود و با یک دستور نصب می‌شود.

چه کارهایی می‌کند:

- SSH مشتری‌ها روی پورت جدا (SSH خود سرور روی پورت ۲۲ دست‌نخورده می‌ماند) و OpenVPN روی UDP و TCP.
- یک کاربر برای هر اشتراک، با تاریخ پایان، محدودیت حجم و محدودیت تعداد دستگاه.
- شمارش دقیق ترافیک هر کاربر (با nftables) هر ۱۰ ثانیه؛ کاربری که از محدودیت رد شود یا تاریخش تمام شود، قفل و قطع می‌شود.
- لیست زنده‌ی کاربران آنلاین، API روی HTTPS، خط فرمان و خودآزمایی (`hubit-node doctor`).
- UDP اختیاری برای تماس تصویری روی SSH (udpgw) که شمرده نمی‌شود.

وضعیت: در حال توسعه‌ی اولیه؛ همه‌ی موارد بالا کار می‌کنند و با هابیت پنل 1.6 به بالا استفاده می‌شوند. بعداً: OpenConnect و پروتکل‌های دیگر.

## نصب و آپدیت

روی اوبونتو یا دبیان، با کاربر root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/hubit-git/hubit-node/main/install.sh)
```

بار اول **می‌پرسد** چه چیزی اجرا شود (Enter مقدار داخل کروشه را می‌پذیرد): آدرسی که مشتری‌ها وصل می‌شوند، پروتکل‌ها
(`ssh`، `openvpn` یا هر دو)، پورت SSH، پورت UDP و TCP اوپن‌وی‌پی‌ان (یا `off`)، udpgw (بله یا خیر) و پورت API. هر پورت را چک می‌کند: اگر
برنامه‌ای روی سرور آن را دارد، می‌گوید کدام برنامه است و یک پورت آزاد پیشنهاد می‌دهد. آخر خلاصه نشان می‌دهد، تأیید می‌گیرد و دستورهای
فایروال را برای پورت‌هایی که انتخاب کردی چاپ می‌کند. آپدیت (وقتی تنظیمات از قبل هست) هیچ سؤالی نمی‌پرسد.

برای نصب بدون سؤال (اسکریپت، چند سرور)، متغیرها را بگذار و `HUBIT_YES=1`: `HUBIT_HOST`، `HUBIT_PROTOCOLS`
(`ssh,openvpn`)، `HUBIT_SSH_PORT`، `HUBIT_UDP_PORT`، `HUBIT_TCP_PORT` (عدد یا `off`)، `HUBIT_API_PORT`، `HUBIT_UDPGW` (`yes` یا
`no`). اگر ترمینال نباشد هم بدون سؤال اجرا می‌شود. پورتی که از قبل استفاده می‌شود نصب را با یک پیام متوقف می‌کند.

اگر Docker نباشد نصبش می‌کند، IP forwarding را روشن می‌کند (کلاینت‌های OpenVPN از طریق سرور مسیر می‌گیرند)، پروژه را در
`/opt/hubit-node` می‌گذارد، کانتینر `hubit-node` را بالا می‌آورد، دستور `hubit-node` را اضافه می‌کند و پورت API، کلید و اثر انگشت
گواهی را که هابیت لازم دارد چاپ می‌کند.

**برای آپدیت همین دستور را دوباره بزن.** داده‌های `/opt/hubit-node/data` می‌مانند (تنظیمات، کاربران، گواهی‌ها). بعد از آپدیت
`hubit-node doctor` را بزن: باید به `all good` ختم شود (هشدار درباره‌ی فایروال هاستینگ عادی است، بخش [فایروال](#فایروال) را ببین).

ایمیج را GitHub Action با نام «Build image» با هر push به `main` و با تگ‌هایی مثل `v0.3.0` می‌سازد و روی
`ghcr.io/hubit-git/hubit-node` منتشر می‌کند. اگر ایمیج منتشرشده نباشد، `install.sh` آن را روی خود سرور می‌سازد.

## راه‌اندازی اول، قدم به قدم

نصب‌کننده آدرس و پورت‌ها را از قبل پرسیده است. بعد روی نود:

```bash
hubit-node doctor                   # ۱. بررسی سرور
hubit-node api                      # ۲. پورت، کلید و اثر انگشت: در هابیت لازمشان داری
hubit-node host vpn.example.com     # (فقط برای عوض‌کردن آدرس بعداً)
```

گواهی OpenVPN روی نود ساخته نمی‌شود: یک بسته در هابیت پنل آپلود می‌کنی (پنل‌ها ← «OpenVPN certificate») و هابیت آن را به همه‌ی نودها
می‌فرستد. اگر فقط یک نود را تنها تست می‌کنی، `hubit-node pki create` یک بسته همین‌جا می‌سازد؛ بسته‌ای که این‌طور ساخته شود، وقتی
در هابیت یکی آپلود کنی جایگزین می‌شود.

پورت‌ها را در فایروال باز کن ([فایروال](#فایروال)) و بعد نود را در هابیت اضافه کن.

## اضافه‌کردن نود به هابیت پنل

در پنل ادمین، پنل‌ها ← پنل جدید، نوع **Hubit node**:

| فیلد | مقدار |
|---|---|
| آدرس | `https://SERVER:8443` (پورت API از `hubit-node api`) |
| کلید API | همان `key` از `hubit-node api` |
| اثر انگشت | همان `fingerprint` از `hubit-node api` (۶۴ رقم هگز؛ دونقطه و فاصله اشکالی ندارد) |

بعد **همگام‌سازی گروه‌ها** را بزن. نود سه گروه دارد که هر کدام مجموعه‌ای از پروتکل‌هاست:

| گروه | کاربر چه می‌گیرد |
|---|---|
| `ssh` | فقط SSH |
| `openvpn` | فقط OpenVPN |
| `ssh+openvpn` | هر دو |

هر سرویس را به گروهی وصل کن که باید بفروشد (سرویسی که گروه ندارد `ssh` می‌گیرد). مشتری‌ای که آن سرویس را بخرد دقیقاً همان پروتکل‌ها را
می‌گیرد. برای فروش یک پکیج در چند پروتکل، بخش «فروش در سرویس‌های دیگر» در فرم پکیج هابیت را ببین.

پنل نود را با اثر انگشت گواهی‌اش می‌شناسد، قبل از اینکه کلید فرستاده شود. نودی که **بدون داده‌هایش** دوباره نصب شود، گواهی جدید
می‌سازد: `hubit-node api` را بزن و اثر انگشت جدید را به هابیت بده.

## کار روزمره: خط فرمان

همه‌چیز `hubit-node <دستور>` روی خود نود است. کاربرانی که در هابیت ساخته می‌شوند از هابیت مدیریت می‌شوند؛ دستورهای زیر برای تست و
درست‌کردن دستی چیزها هستند.

### نگاه‌کردن به نود

| دستور | کار |
|---|---|
| `hubit-node status` | نسخه، پورت‌ها، پروتکل‌های روشن، تعداد کاربران |
| `hubit-node doctor` | سرور را بررسی می‌کند (tun، forwarding، قوانین، پورت‌ها، فایروال، API، گواهی، حلقه‌ی محدودیت‌ها) و می‌گوید هر خرابی را چطور درست کنی |
| `hubit-node online` | الان چه کسی وصل است: کاربر، پروتکل، IP کلاینت، چه مدت |

### آدرس‌ها و پورت‌ها

| دستور | کار |
|---|---|
| `hubit-node host vpn.example.com` | آدرسی که مشتری‌ها برای همه‌ی پروتکل‌ها می‌گیرند (`auto` = آدرس همین سرور) |
| `hubit-node host --ssh ssh.example.net` | SSH با آدرس جدا؛ OpenVPN همان آدرس اصلی را نگه می‌دارد. `--openvpn` هم همین‌طور؛ `default` برمی‌گرداند به آدرس اصلی |
| `hubit-node host` | آدرس‌های فعلی را نشان می‌دهد |
| `hubit-node ssh-port 2222` | پورت SSH مشتری‌ها |
| `hubit-node openvpn` | پورت‌های OpenVPN را نشان می‌دهد |
| `hubit-node openvpn --udp 1194 --tcp 443` | عوضشان می‌کند؛ یک پورت یا `off` (حداقل یکی از دو تا روشن می‌ماند) |
| `hubit-node ssh-udpgw 7300` | UDP برای تماس تصویری روی SSH؛ `0` = خاموش ([جزئیات](#udp-برای-تماس-تصویری-روی-ssh-udpgw)) |
| `hubit-node api --port 8443` | پورت API (نه پورتی که SSH یا OpenVPN دارند) |
| `hubit-node api --new-key` | کلید API جدید؛ **کلید جدید را به هابیت بده** |
| `hubit-node api` | پورت، کلید و اثر انگشت API را نشان می‌دهد |

بعد از عوض‌کردن پورت، آن را در فایروال باز کن. مشتری‌ها فقط وقتی فایل OpenVPN جدید لازم دارند که پورت یا آدرس OpenVPN عوض شده باشد.

### پروتکل‌ها

```bash
hubit-node protocol list              # کدام پروتکل‌ها روشن‌اند
hubit-node protocol disable ssh       # اول کار، بعد اسم (ssh یا openvpn)
hubit-node protocol enable ssh
```

کاربر و گروهش وقتی پروتکلی خاموش است سر جایشان می‌مانند؛ گروه فقط پروتکل‌های روشن را می‌دهد.

### کاربران

```bash
hubit-node user add ali --password Abc12345 --group openvpn --days 30 --data 50 --devices 2
hubit-node user list                  # همه‌ی کاربران: گروه، وضعیت، آنلاین، مصرف، محدودیت، دستگاه، پایان
hubit-node user show ali
hubit-node user set ali --days 60 --data 100      # عوض‌کردن محدودیت‌ها یا --group
hubit-node user passwd ali --password Xyz98765
hubit-node user disable ali           # قفلش می‌کند و قطعش می‌کند
hubit-node user enable ali
hubit-node user kick ali              # اتصال‌هایش را همین الان می‌بندد؛ حساب می‌ماند
hubit-node user reset-usage ali       # مصرف را به صفر برمی‌گرداند
hubit-node user del ali
```

گزینه‌های محدودیت (برای `add` و `set`):

| گزینه | معنی |
|---|---|
| `--days N` | N روز از الان تمام می‌شود |
| `--expire "YYYY-MM-DD HH:MM:SS"` | در این زمان تمام می‌شود، به وقت **UTC** (`none` = بی‌پایان) |
| `--data GB` | محدودیت حجم به گیگابایت (`0` = نامحدود) |
| `--devices N` | تعداد دستگاه همزمان (`0` = نامحدود)؛ بدون آن، `add` مقدار ۱ می‌گذارد |
| `--group NAME` | `ssh`، `openvpn`، `ssh+openvpn` (پیش‌فرض `ssh`) |

بدون `--password`، `add` یک رمز تصادفی می‌سازد و چاپ می‌کند. رمز ۸ تا ۶۴ کاراکتر است.

## محدودیت‌ها چطور کار می‌کنند

- **حجم.** هر بسته‌ی هر کاربر در هر دو جهت شمرده می‌شود و هر ۱۰ ثانیه به مصرفش اضافه می‌شود. SSH با حساب لینوکسی کاربر شمرده می‌شود
  (ترافیک تونل با همان حساب از سرور بیرون می‌رود) و OpenVPN از شمارنده‌ی بایت خود OpenVPN برای هر نشست (عددهای نشستی که تمام شده
  نگه داشته می‌شوند). وقتی مصرف به محدودیت برسد، کاربر قفل و قطع می‌شود. ترافیک loopback و بخش udpgw شمرده نمی‌شوند.
- **زمان.** در زمان پایان، کاربر قفل و قطع می‌شود.
- **دستگاه.** *دستگاه* یعنی یک **آدرس IP کلاینت**. دو گوشی پشت یک مودم خانگی یک IP عمومی دارند، پس **یک** دستگاه حساب می‌شوند؛ گوشی با
  اینترنت موبایل IP دیگری دارد و دستگاه دوم است. تا وقتی سقف پر است، ورود جدید از IP جدید **رد می‌شود** (اپ فقط می‌گوید «نام کاربری
  یا رمز اشتباه است»: SSH و OpenVPN نمی‌توانند پیام دیگری نشان بدهند). اتصال از IPی که از قبل وصل است همیشه مجاز است. اگر دستگاه اضافه
  رد شود (وقتی خود بررسی خراب شود عمداً اجازه‌ی ورود می‌دهد تا باگ کسی را بیرون نیندازد)، حلقه IPهای جدیدتر را ظرف ۱۰ ثانیه می‌بندد.
- **پشت تانل ریورس** (سروری در جلو که کلاینت‌ها را به نود می‌رساند، «backhaul») همه‌ی کلاینت‌ها با آدرس `127.0.0.1` به نود می‌رسند و
  آی‌پی چیزی نمی‌گوید. برای آدرس loopback هر **اتصال** یک دستگاه است: با `devices 1` اوپن‌وی‌پی‌ان تا وقتی اتصال اول زنده است اتصال دوم را
  رد می‌کند (اتصالی که تمیز تمام شود فوراً فراموش می‌شود؛ اتصالی که ناگهان از بین برود، مثل گوشی که شبکه عوض می‌کند، تا حدود ۱۵ ثانیه) و SSH می‌گذارد **جدیدترین** برنده شود: ورود پذیرفته می‌شود و اتصال
  قدیمی‌تر ظرف ۱۰ ثانیه بسته می‌شود، پس مشتری‌ای که دوباره وصل می‌شود هیچ‌وقت با یک اتصال مرده قفل نمی‌شود. اپی که برای یک ورود چند اتصال SSH باز
  کند، آنجا چند دستگاه حساب می‌شود. کلاینت‌های با آدرس واقعی مثل بالا با آی‌پی شمرده می‌شوند.
- **پیام در اپ.** بعد از ورود درست به SSH، نود یک خط برای کلاینت می‌فرستد: `Used 3.20 GB of 10.00 GB | 24 days left`
  (یا `(no data limit)`، `ended`). اپ‌هایی مثل NetMod می‌توانند آن را در لاگ خود نشان بدهند؛ مصرفِ لحظه‌ی ورود است و زنده نیست،
  پس مشتری برای دیدن عدد تازه دوباره وصل می‌شود. اوپن‌وی‌پی‌ان چنین چیزی نشان نمی‌دهد.
- **کاربران قفل‌شده** با مصرفشان روی نود می‌مانند تا دوباره فعال شوند (هابیت با API تمدید یا فعالشان می‌کند).

## آدرس‌ها و پورت‌ها

پیش‌فرض‌ها: API روی `8443/tcp`، SSH روی `2222/tcp`، OpenVPN روی `1194/udp` و `1194/tcp` (در تنظیم شما ممکن است فرق کند؛ `hubit-node status`
نشانشان می‌دهد). مشتری‌ها یک فایل OpenVPN با هر دو خط `remote` می‌گیرند، اول UDP: کلاینت UDP را امتحان می‌کند و بعد از ۵ ثانیه
بی‌پاسخی، TCP را. شبکه‌ای که UDP را می‌بندد خودبه‌خود به TCP می‌افتد.

برای آدرس نود از رکورد **DNS only** استفاده کن (بدون پراکسی CDN مثل ابر نارنجی Cloudflare).

## فایل OpenVPN و گواهی

- یک بسته (ca، گواهی سرور، کلید سرور، کلید tls-crypt) برای همه‌ی نودها مشترک است. چون فایل مشتری فقط ca و کلید tls-crypt را دارد،
  **فایل مشتری وقتی نودی عوض شود هم کار می‌کند**، به شرط اینکه بسته همان باشد. گواهی بسته سال‌ها معتبر است (`hubit-node doctor` نشان می‌دهد کی تمام می‌شود).
- یک بار در هابیت آپلودش کن (پنل‌ها ← «OpenVPN certificate»). هابیت وقتی ذخیره شود و وقتی نودی اضافه یا ویرایش شود، آن را به همه‌ی نودهای
  Hubit فعال می‌فرستد؛ نودی که خاموش بوده با دکمه‌ی «ارسال» همان‌جا می‌گیرد.
- دستی: `hubit-node pki create` (بسته‌ی جدید، فقط اگر هیچ بسته‌ای نیست)، `pki import < bundle.tgz`، `pki export > bundle.tgz`،
  `pki show` (کی تمام می‌شود).
- `hubit-node ovpn > client.ovpn` فایل کلاینت را چاپ می‌کند: برای همه‌ی مشتری‌ها یکی است (نام کاربری و رمز در اپ تایپ می‌شود). هابیت هم آن را
  به مشتری می‌دهد (دانلود، QR برای OpenVPN Connect نسخه‌ی 3.3.6 به بعد، لینک).
- اپ مشتری نام کاربری و رمز اشتراک را می‌خواهد؛ هابیت آن‌ها را در جزئیات اشتراک نشان می‌دهد.

## UDP برای تماس تصویری روی SSH (udpgw)

SSH فقط TCP حمل می‌کند، پس تماس تصویری (واتس‌اپ، تلگرام، اینستاگرام) روی یک تونل SSH ساده کند است یا وصل نمی‌شود. برای همین نود
[badvpn-udpgw](https://github.com/ambrop72/badvpn) را روی `127.0.0.1:7300` اجرا می‌کند (فقط روی خود سرور، هیچ‌وقت به اینترنت باز نیست). اپی مثل
NetMod یا HTTP Injector بسته‌های UDP را داخل تونل SSH به آن می‌دهد و آن بیرون می‌فرستدشان.

- مشتری در اپ **UDPGW** را روشن می‌کند و `127.0.0.1:7300` را می‌نویسد. هابیت این خط را در جزئیات اتصال نشان می‌دهد.
- در مصرف کاربر **شمرده نمی‌شود**، عمداً: فقط UDP حمل می‌کند و بخش داخل تونل روی loopback است. پس ترافیک سنگین UDP (مثلاً ویدیوی QUIC)
  بدون شمارش رد می‌شود. اگر این برایت مشکل است، خاموشش کن.
- `hubit-node ssh-udpgw 7300` پورت را می‌گذارد، `hubit-node ssh-udpgw 0` خاموشش می‌کند.
- OpenVPN به هیچ‌کدام از این‌ها نیاز ندارد: خودش UDP حمل می‌کند و می‌شمارد.

## فایروال

روی سرور باز کن (نمونه با ufw):

```bash
ufw allow 2222/tcp     # SSH مشتری‌ها
ufw allow 1194/udp     # OpenVPN روی UDP
ufw allow 1194/tcp     # OpenVPN روی TCP (پورت‌های خودت را بگذار)
ufw allow 8443/tcp     # API: هابیت اینجا وصل می‌شود (می‌توانی فقط IP پنل را مجاز کنی)
```

`hubit-node doctor` وقتی ufw فعال باشد هشدار می‌دهد. فایروال سایت هاستینگ (Hetzner، OVH و ...) را از داخل سرور نمی‌بیند: همین پورت‌ها را
آنجا هم باز کن. کانتینر از شبکه‌ی خود سرور استفاده می‌کند، پس گزینه‌ی `-p` در کار نیست.

## جابه‌جایی یا ساخت دوباره‌ی سرور

- **از `/opt/hubit-node/data` نسخه‌ی پشتیبان بگیر**: `config.json` (تنظیمات)، `hubit.db` (کاربران و مصرف)، `pki/` و `api/` (گواهی‌ها). آن را قبل از
  اولین شروع روی سرور جدید برگردان تا نود مثل قبل بالا بیاید؛ کاربران لینوکسی هر بار شروع از روی دیتابیس دوباره ساخته می‌شوند.
- **بدون داده‌ها**، نود خالی است و گواهی API جدید دارد: کاربرانش رفته‌اند (دوباره اضافه کن) و هابیت اثر انگشت جدید را لازم دارد. فایل OpenVPN
  مشتری‌ها تا وقتی بسته همان باشد کار می‌کند (دوباره در هابیت آپلودش کن).
- برای عوض‌کردن آدرس سرور بدون خراب‌شدن فایل مشتری‌ها از **دامنه** استفاده کن و رکوردش را جابه‌جا کن.

## عیب‌یابی

| نشانه | کار |
|---|---|
| هر چیز نامعلوم | `hubit-node doctor` و بعد `docker logs hubit-node --tail 50` |
| «نام کاربری یا رمز اشتباه» در اپ | رمز اشتباه است، **یا** سقف دستگاه پر است (IP دیگری وصل است: `hubit-node online`)، **یا** کاربر قفل یا تمام‌شده است (`hubit-node user show NAME`) |
| دو دستگاه در خانه قطع نمی‌شوند | یک IP عمومی دارند، پس یک دستگاه‌اند ([محدودیت‌ها چطور کار می‌کنند](#محدودیتها-چطور-کار-میکنند)) |
| هابیت می‌گوید نود در دسترس نیست | پورت API در یک فایروال بسته است، نود خاموش است (`docker ps`)، یا کلید عوض شده |
| هابیت می‌گوید گواهی نمی‌خواند | نود بدون داده‌هایش دوباره نصب شده: `hubit-node api` را بزن و اثر انگشت جدید را به هابیت بده |
| OpenVPN گوش نمی‌دهد | هنوز گواهی نیست: بسته را در هابیت آپلود کن (یا برای تست `hubit-node pki create`) |
| OpenVPN وصل می‌شود ولی اینترنت نیست | forwarding خاموش است یا سیاست FORWARD داکر جلویش را می‌گیرد: `hubit-node doctor` می‌گوید کدام، `docker restart hubit-node` قوانین را دوباره می‌گذارد |
| `hubit-node` خطای `Resource temporarily unavailable` می‌دهد (و در `journalctl -k` عبارت `fork rejected by pids controller` هست) | کانتینر به سقف تعداد پروسس رسیده. `docker-compose.yml` حالا `pids_limit: 100000` دارد: آپدیت کن (دستور نصب) تا کانتینر دوباره با آن ساخته شود و بررسی کن `cat /sys/fs/cgroup/system.slice/docker-$(docker inspect -f '{{.Id}}' hubit-node).scope/pids.max` عدد 100000 بدهد. سقف خود سرور یعنی `kernel.threads-max` هم باید از آن بیشتر باشد. اگر باز هم شد، ببین چه چیزی زیاد می‌شود: `ps -eo comm --no-headers \| sort \| uniq -c \| sort -rn \| head` |
| `doctor` می‌گوید حلقه‌ی محدودیت‌ها اجرا نشده | `docker logs hubit-node 2>&1 \| grep -i loop` |
| مصرف بالا نمی‌رود | حلقه کار نمی‌کند (بالا را ببین)، یا کاربر ترافیکی نساخته |

## API

HTTPS با گواهی خودامضا (هابیت اثر انگشتش را چک می‌کند: `hubit-node api` چاپش می‌کند)، کلید در هدر `X-API-Key`. زمان‌ها UTC با شکل
`YYYY-MM-DD HH:MM:SS`، حجم به بایت، نام کاربر `[a-z][a-z0-9_-]*`.

| درخواست | کار |
|---|---|
| `GET /info` | نسخه، آدرس، پروتکل‌ها، تعداد کاربران و کاربران آنلاین |
| `GET /groups` | گروه‌ها و پروتکل‌هایشان |
| `GET /users?offset=&limit=` | کاربران (`limit` تا ۵۰۰۰) |
| `POST /users` | `username`، `password` (۸ کاراکتر یا بیشتر)، `group`، `expire_at`، `data_limit`، `devices` |
| `GET\|PATCH\|DELETE /users/{u}` | خواندن، تغییر (با `password` هم) یا حذف (حذف کاربری که نیست اشکالی ندارد) |
| `POST /users/{u}/disable\|enable\|reset-usage\|kick` | کارها |
| `GET /users/{u}/connection` | آنچه کاربر برای وصل‌شدن لازم دارد: `[{protocol, host, port\|udp\|tcp, udpgw}]` |
| `GET /online` | اتصال‌های زنده |
| `GET /profile/openvpn` | فایل `.ovpn` (متن) |
| `GET\|PUT /pki` | وضعیت بسته؛ `PUT` یک JSON با چهار فایل به‌صورت متن می‌گیرد (`ca.crt`، `server.crt`، `server.key`، `tls-crypt.key`) |

## ساختار پروژه

پوشه‌ی `hubit_node/modules/` برای هر پروتکل یک فایل دارد (`ssh.py`، `openvpn.py`)؛ هسته هیچ پروتکلی را با نام نمی‌شناسد، پس پروتکل جدید یک
فایل جدید است. `hubit_node/supervisor.py` پردازه‌ی شماره‌ی ۱ کانتینر است (پردازه‌ها و حلقه‌ی ۱۰ ثانیه‌ای را اجرا می‌کند)،
`api.py` همان API، `cli.py` خط فرمان و `doctor.py` خودآزمایی.
